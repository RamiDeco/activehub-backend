COMO SE MANTIENE ESTE ARCHIVO
- Se registra todo cambio del sistema que pueda afectar el informe final. No se redacta el informe: se registran hechos precisos, completos y verificables.
- Hay una copia espejo en el otro repositorio (activehub-backend y activehub-frontend). Las dos se mantienen iguales, salvo las dos lineas del encabezado.
- El bloque ESTADO GENERAL se REEMPLAZA en cada actualizacion. Las entradas SOLO SE AGREGAN: nunca se borra ni se reescribe una entrada anterior; si algo cambio, se agrega una entrada nueva que lo aclare.
- Cuando escribir: al terminar cada tarea o grupo de commits relacionados, y siempre antes de cerrar la sesion de trabajo (actualizando tambien ESTADO GENERAL).
- Espanol, texto plano, sin Markdown. Hechos concretos: nombres, numeros, versiones y codigos.
- Se distingue IMPLEMENTADO (codigo hecho), PROBADO (con prueba automatizada o manual efectivamente ejecutada), PARCIAL, PENDIENTE y RETIRADO. NUNCA se marca como probado algo que no se ejecuto.
- Los numeros se obtienen ejecutando comandos, no estimando (casos de uso, archivos de prueba y pruebas con el resultado de la suite, migraciones, ESLint). Se indica el comando usado.
- Los textos de interfaz nuevos o modificados se copian LITERALES (botones, campos con * si son obligatorios, titulos, mensajes de error y de exito, dialogos de confirmacion). Se usan para el manual de usuario.
- Si un cambio modifica un comportamiento existente, se describe el comportamiento nuevo completo, no solo la diferencia.
- SEGURIDAD: nunca se escriben contrasenias reales, tokens, claves de API ni cadenas de conexion. De las variables de entorno, solo el nombre. Usuarios de prueba solo si son cuentas de demostracion, marcadas como tales.
- Si se crea una pantalla, una historia de usuario o una regla nueva, se propone el codigo siguiente de su serie y se marca como NUEVO.
- Si se reemplaza una tecnologia o se cambia una decision de diseno: que habia antes, que hay ahora, por que, que alternativas se evaluaron y que impacto tiene.
- Cada vez que avanza un item de PENDIENTES CONOCIDOS se indica explicitamente, por ejemplo: "PENDIENTE 1: PENDIENTE -> PROBADO".
